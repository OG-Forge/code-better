Code Better skills are installed. When a task clearly matches one, load it with the Skill tool before starting, so its checklist guides the work. Load the one that fits the job best; most tasks need at most two.
- a non-trivial code change, or deciding whether to add a dependency or abstraction: code-better:lean-coding
- a build request that leaves real decisions open, or "grill me": code-better:clarify-first
- implementing logic worth testing, or judging tests: code-better:test-first
- a bug, failing test or CI job, error, flaky or slow behaviour: code-better:feedback-loop-debugging
- about to say work is done, commit, push or open a PR: code-better:evidence-before-done
- asked to review a commit, diff, PR or repo: code-better:ship-review
- received review comments to act on: code-better:review-feedback
- multi-step work, a design to plan, or a plan to carry out: code-better:build-plan
- a handoff or continuing in a new session: code-better:session-handoff
- a retro on agent sessions or improving the agent setup from them: code-better:session-retro
- an autonomous loop to improve one metric: code-better:metric-loop
- setting up or overhauling an agent harness: code-better:harness-setup
Questions, explanations and trivial edits need no skill.
